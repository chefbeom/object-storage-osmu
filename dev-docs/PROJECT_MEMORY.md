# OSMU Project Memory

이 문서는 프로젝트의 최종 목표, 방향성, 장기 기능을 잊지 않기 위해 유지하는 기준 문서이다.

구현 중 세부 기능이나 기술 선택이 바뀌더라도, 이 문서의 방향은 프로젝트의 북극성으로 사용한다.

## 1. 최종 목표

OSMU의 최종 목표는 기업이 자체 인프라에서 대용량 파일을 안전하게 저장, 관리, 공유, 재사용할 수 있는 B2B 프라이빗 오브젝트 스토리지 플랫폼을 완성하는 것이다.

완성된 제품은 특정 회사 내부 시스템에만 묶이지 않고, 다양한 기업 환경에 설치해서 사용할 수 있어야 한다.

최종적으로는 다음 고객에게 판매할 수 있는 수준을 목표로 한다.

- 스트리밍 플랫폼
- 클라우드 스토리지 플랫폼
- 자체 스토리지 저장 플랫폼이 필요한 기업
- AWS S3 대신 내부 S3 호환 스토리지를 쓰고 싶은 기업
- 대용량 이미지, 영상, 비디오, 문서, 로그, AI 학습 데이터를 저장해야 하는 기업
- 보안, 비용, 데이터 통합 관리 문제를 해결하려는 조직

## 2. 제품 한 줄 정의

기업이 AWS S3 같은 외부 클라우드 스토리지에 의존하지 않고, 자체 인프라 위에서 대용량 파일을 저장, 관리, 공유, 백업, 재사용할 수 있게 해주는 S3 호환 프라이빗 오브젝트 스토리지 플랫폼.

## 3. 반드시 유지해야 하는 핵심 방향

- 파일 형식과 확장자에 구애받지 않고 저장할 수 있어야 한다.
- 영상, 이미지, 비디오, 문서, 로그, 백업 파일, AI 학습 데이터 등 대용량 비정형 데이터를 다룰 수 있어야 한다.
- REST API로 접근할 수 있어야 한다.
- S3 API 호환 클라이언트로 직접 접근할 수 있어야 한다.
- FUSE, goofys, s3fs-fuse 같은 파일시스템 마운트 방식을 고려해야 한다.
- 기업 내부의 통합 스토리지 시스템 역할을 해야 한다.
- 부서 간 데이터 공유를 효율화해야 한다.
- 외부 저장소 사용에 따른 보안 위험을 줄여야 한다.
- 외부 클라우드 장기 사용 비용을 줄일 수 있어야 한다.
- 중앙 집중식 관리로 중복 저장과 관리 부담을 줄여야 한다.
- 단순 파일 업로드 서비스가 아니라, 설치형 B2B 스토리지 플랫폼으로 성장해야 한다.

## 4. 최종 제품이 해결해야 하는 문제

현재 많은 기업은 AWS S3, FTP 서버, USB, 외장 하드디스크, NAS, 개별 서버 디스크, 부서별 저장소를 혼합해서 사용한다.

이로 인해 다음 문제가 발생한다.

- 통합된 스토리지 시스템 부재
- 부서 간 데이터 공유 비효율
- 개별 스토리지 운영에 따른 관리 부담
- 데이터 접근 제한과 권한 관리 어려움
- 외부 저장소 사용에 따른 데이터 유출 위험
- 물리 저장 장치 분실에 따른 보안 위협
- 장기적인 외부 스토리지 비용 부담
- 중복 저장 증가
- 백업과 복구 체계 분산
- 대용량 파일 재사용 어려움

OSMU는 이 문제들을 해결해야 한다.

## 9. 잊지 말아야 할 판단 기준

새 기능을 추가할지 고민할 때 다음 질문으로 판단한다.

- 이 기능이 기업 내부 대용량 파일 저장 문제를 해결하는가?
- 이 기능이 S3 대체 또는 보완 제품으로서 가치를 높이는가?
- 이 기능이 보안, 비용, 데이터 공유, 운영 효율 중 하나를 개선하는가?
- 이 기능이 설치형 B2B 제품으로 판매 가능성을 높이는가?
- 이 기능이 MVP를 너무 늦추지는 않는가?
